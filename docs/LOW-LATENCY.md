# Pi5: 8×8 / 192 кГц / PCM32, версия 2.2

[Установка](BUILD.md) · [RT-образ](RT-IMAGE.md) · [Протокол v3](https://github.com/danrey-bilo/AoIP-lib/blob/main/docs/PROTOCOL-V3.md)

Базовый профиль — 8 входов и 8 выходов, 192000 Гц, знаковый целочисленный PCM32.
Windows ASIO32 получает блок каждые 0,167 мс. Pi передаёт до 24 кадров (0,125 мс),
готовый выходной ASIO-блок отправляется сразу, фрагментация только по MTU.
Для универсального драйвера сохранены 1–64 физических канала, независимые
направления, PCM16/24/32 и 44,1–192 кГц. Формат меняется через панель Windows.

Ethernet: ПК 192.168.1.1/24, Pi 192.168.1.2/24, маска 255.255.255.0, Gigabit
full duplex. LAN не имеет маршрута в Интернет; Wi-Fi остаётся доступным.
Pi macb/RP1: rx-usecs=0, tx-usecs=0, EEE off. На тестовом Intel I225-V
Interrupt Moderation уже отключён; checksum offload сохраняется.
Число дескрипторов кольца не является фиксированным ожиданием пакета.

## Активность

v3 передаёт маски физических каналов; отключённый канал отсутствует в PCM
пакета. При включённом энергосбережении учитываются каналы, открытые хостом.
Точный цифровой ноль подавляется без порога по уровню. Нулевое направление
получает три коротких уведомления, затем аудиотрафик отсутствует; следующий
ненулевой блок не требует нового подключения. Stop немедленно отписывается;
после аварии хоста трафик прекращается по 3-секундной аренде.

Windows [меню каналов, энергосбережение и трей](https://github.com/danrey-bilo/Win11-asio-AoIP/blob/main/docs/ENERGY-SAVING.md).
Синтетический peer генерирует тестовые тоны; физический ADC/DAC, I2S и эффекты
ещё не реализованы. Проверки относятся к цифровому транспорту.

## Критерии проверки

Восьмиканальный тест возвращает Pi → ASIO callback → Pi; содержит p50/p95/p99/max
RTT, startup до первого callback, пропуски/опоздания PCM, deadline misses,
skipped frames, очереди, expired TX, CRC, разрывы RX и CPU каждого ядра Pi.
`lost=0` само по себе не подтверждает непрерывность звука.
На этом ПК выявлены паузы Windows порядка 2,4–2,5 мс: guard64 и guard448
не проходят проверку стабильности. Guard480 дал редкие пропуски в 180-секундном
прогоне. Итоговый guard512 прошёл 180 секунд без пропусков, переполнений и
expired TX; это запас против джиттера, а не ожидание внутри Ethernet-драйвера.
Конкретные результаты: [валидация](VALIDATION.md), полный журнал — в private
AoIP-debug-tool и локальном пакете 2.2. Требование 20 мс относится к запуску
ASIO на уже готовом Pi, не к загрузке Linux.

PREEMPT_RT, CPU0/CPU1 для сети, CPU2/CPU3 для будущих эффектов, Wi-Fi,
Bluetooth, USB, Ethernet и GPIO сохраняются. Образ формируется по LAN прямо
на диске ПК через NBD/SSH. Проверка файловой системы и содержимого образа
отделена от фактической загрузки с него: отдельно записанный новый носитель
в этом тесте не загружался.
