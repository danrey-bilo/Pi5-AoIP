# Проверки Pi5 AoIP — 2026-09-29

Актуальная проверка 2.3.1 приведена ниже. Разделы 2.1 и 2.2 сохранены как
история и не описывают текущий установленный профиль.

## Версия 2.3.1 — 8×8 / 192 кГц / PCM32

Raspberry Pi 5 Model B 4 ГБ, Raspberry Pi OS Lite 64-bit / Debian 13,
`6.18.50+rpt-rpi-v8-rt`, PREEMPT_RT. ПК: Windows 11 x64 / Intel I225-V,
выделенный Gigabit LAN `192.168.1.1/24` ↔ `192.168.1.2/24`. Wi-Fi остаётся
подключённым независимо. Проверены live-служба, ARM64 runtime/SDK
`2.3.1-1`, CTest 4/4 на Pi и 4/4 на Windows. Потребитель установленного SDK
через `find_package(Pi5AoIP 2.3.1 CONFIG REQUIRED)` прошёл проверку Pi/RT,
всех четырёх ролей на CPU0 и FIFO70 для RX/TX.

Служба на Pi использует CPU0 для TX, RX, control и reporter; у всех TID
`Cpus_allowed_list=0`. IRQ `eth0` также назначен CPU0 (номер обнаруживается
при запуске, а не зашит в драйвер). За 30 секунд активной передачи служба
заняла 15,50% одного CPU0 по `/proc/TID/schedstat`; CPU1/2/3 — 0% **для
этой службы**. В нагрузку всего ядра входят и другие задачи ОС и IRQ.
`rx-usecs=0`, `tx-usecs=0`, EEE выключен; на Intel I225-V Interrupt
Moderation и DMA Coalescing выключены. Системные power plan, MMCSS и
глобальные сетевые параметры Windows не менялись. Wi-Fi, Bluetooth service,
USB root hubs и GPIO devices остались доступны; `throttled=0x0`.

Цифровой синтетический тракт Pi → Windows ASIO callback → Pi,
8 сконфигурированных входов и 8 выходов, PCM32, подписка v3, маски
`ff`/`ff`, capture16 кадров. Физический ADC/DAC тракт отсутствует.
Каждая строка — отдельный 180-секундный прогон. `Input/Output/Overall` —
значения, **сообщаемые ASIO**, а RTT — независимо измеренный цифровой круг;
они измеряют разные вещи.

| ASIO/LAN, кадров | Input / Output / Overall, мс | RTT p50 / p99 / max, мс | PCM missing / late | Deadline miss | Callback сверх периода |
|---|---|---|---:|---:|---:|
| 64/256 | 1,750 / 0,333 / 2,083 | 1,695 / 1,783 / 2,777 | 16 / 16 | 1 | 0 |
| 64/320 | 2,083 / 0,333 / 2,417 | 2,027 / 2,113 / 4,025 | 80 / 80 | 0 | 0 |
| **64/448 №1** | **2,750 / 0,333 / 3,083** | **2,695 / 2,788 / 4,223** | **0 / 0** | **0** | **0** |
| **64/448 №2** | **2,750 / 0,333 / 3,083** | **2,696 / 2,785 / 4,182** | **0 / 0** | **0** | **0** |
| 64/512 | 3,083 / 0,333 / 3,417 | 3,032 / 3,121 / 4,599 | 0 / 0 | 0 | 0 |
| 32/512 | 2,917 / 0,167 / 3,083 | 2,869 / 2,963 / 4,135 | 0 / 0 | 0 | 1 |

В двух прогонах 64/448 вместе: примерно 4,32 млн RX и 2,16 млн TX пакетов
Windows, около 2,15 млн RTT-маркеров. Invalid/CRC, RX/TX queue overflow,
resync, skipped frames, expired TX, TX errors, MMCSS failures, ASIO time errors
и host overruns — ноль. Pi за оба прогона: lost/bad/skipped_source_frames/
tx_expired — ноль. Out-of-order на Pi: 10 и 9, без потери PCM. На Windows
максимальные RX gap 1,947 и 1,744 мс, callback 218,7 и 129,7 мкс при
периоде ASIO64 333,3 мкс. Минимальный RTT 2,532 мс в обоих прогонах,
p95 2,768 мс. После 360 чистых секунд выбран 64/448; это подтверждение
конкретного тестового окна, а не гарантия для любой DAW-нагрузки.

На установленной DLL 2.3.1 и пользовательском INI 64/448 отдельный 10-секундный
registered-ASIO прогон снова показал Input 2,750 / Output 0,333 / Overall
3,083 мс и нулевые PCM/error счётчики. Старые `Inputs/Outputs` из INI
игнорируются и удаляются при Apply; панель показала неизменяемые 8/8.
На **локальных синтетических** устройствах 4×4/PCM24/96 кГц,
8×8/PCM16/48 кГц и 64×64/PCM32/192 кГц проверены discovery, отказ от
сетевой смены физического count, игнорирование старого INI, маски и сохранение
произвольного LAN buffer. Это не испытания устройств с настоящими 4 или 64
ADC/DAC каналами. Шесть режимов активности и возобновление после тишины
прошли с нулевым фоновым PCM при отключённом направлении; fixture PCM16/24/32
проверил точный ноль и хвост. Обратная совместимость v1/v2 проверена как
функциональность, без квалификации их сетевой задержки.

Обновлённый 4-ГиБ raw/XZ-образ находится на ПК. Его ext4-раздел прошёл
`e2fsck -fn`, FAT boot совпал по SHA256 с исходной копией, версия runtime/SDK
и unit/профиль проверены. XZ полностью распакован и сравнен с SHA256 raw.
**Новый образ 2.3.1 отдельно не загружался с носителя**. Работа RT-ядра и
службы проверена на текущей Pi. ADC/DAC/I²S backend отсутствует, поэтому
измеренная задержка записи от ADC и воспроизведения до DAC неизвестна.

## Версия 2.1 — исторические результаты

Плата: Raspberry Pi 5 Model B Rev 1.1, 4 ГБ. Raspberry Pi OS Lite 64-bit,
Debian 13, ядро `6.18.50+rpt-rpi-v8-rt`, `CONFIG_PREEMPT_RT=y`, страницы 4 КиБ.
AoIP-lib закреплён на `8a787513bc2d0af68102dbafd086325398346c50`.

## Сборка и система

- Нативная ARM64-сборка GCC 14.2.0, Release, `-Wall -Wextra -Werror` прошла.
- Четыре CTest: core, example_core, example_peer, pi5_platform_policy — прошли.
- Тест платформы проверил настоящую affinity и FIFO-приоритет каждой роли,
  модель/RT/изоляцию, отказ выбирать Wi-Fi и несуществующий интерфейс.
- Runtime DEB установлен и служба запущена от пользователя `piaoip`.
- TX: CPU1/FIFO70; RX: CPU0/FIFO70; control/reporter: CPU1/SCHED_OTHER.
- SDK проверен отдельной программой через `find_package(Pi5AoIP 2.1 CONFIG)`
  и экспортированный target `PiAoIP::rpi5`.
- Ethernet 1 Гбит/с full duplex, Wi-Fi, Bluetooth, USB и GPIO доступны после
  загрузки RT; `throttled=0x0`.

30 секунд cyclictest, один поток CPU0, FIFO80, период 1 мс: min 1 мкс,
avg 2 мкс, max 47 мкс. Часть окна включала нативную сборку на CPU0/CPU1.
Это задержка пробуждения планировщика, а не задержка аудио.

## Версия 2.2 — 8×8 / 192 кГц / PCM32

AoIP-lib: `041ec447cc246a0cdb2f4726f646c5aab8017518`. Та же Pi5 4 ГБ,
RT-ядро и Gigabit LAN; ПК Windows 11 / Intel Core i9-13900K / Intel I225-V.
На Pi rx-usecs=0, tx-usecs=0, EEE disabled. На ПК Interrupt Moderation уже
был выключен. Глобальные настройки MMCSS, power plan и сетевого реестра
Windows не менялись.

Профиль: 8 входов + 8 выходов, 192000 Гц, знаковый PCM32, ASIO32,
safety512, capture24, output32/пакет, v3, маски `ff`/`ff`, energy saving on.
Тест возвращает синтетический PCM Pi → ASIO callback → Pi.

|---|---:|
| Измерения | 1 077 180 |

### Запуск, тишина, каналы и трей

После окончательной правки запуска RX проверены 100 повторных Start:
p50 3,581 / p95 3,898 / p99 4,070 / max 4,077 мс.
На реальной Pi с полностью нулевым синтетическим источником ещё 100 Start:
p50 3,700 / p95 4,514 / p99 5,782 / max 6,916 мс. Каждый Start уложился
в 20 мс; это готовый Linux peer, не время загрузки системы.

Пять секунд цифрового нуля: ровно три коротких аудиоуведомления в каждом
направлении и далее ноль аудиопакетов; missing/late/deadline/overflow/expired
TX = 0, ASIO time errors = 0. Callback max 182,4 мкс дал один host overrun
при 32-кадровом периоде: этот счётчик сохранён в журнале. В активном
180-секундном сеансе host overruns = 0. При открытом ASIO-потоке нулевые
callback продолжаются по контракту ASIO; CPU RX/TX за тихое окно = 0,00%,
audio worker = 2,81% одного логического CPU.

Шесть тестов активности подтвердили физические маски, незапрошенные
каналы, output-only, полностью выключенные каналы, энергосбережение off,
переходы ноль/звук и прекращение аудиотрафика после Stop. После аварийного
завершения хоста 3-секундная аренда истекла и счётчики TX/RX замерли.
Loopback fixture PCM16/24/32 подтвердил возобновление первого ненулевого
блока и сохранение хвоста перед тишиной; это функциональный тест, не
измерение аппаратной задержки.

Короткие аппаратные функциональные прогоны по 3 секунды: 8×8/48 кГц/PCM16,
4×4/96 кГц/PCM24 и 64×64/192 кГц/PCM32 (ASIO128). Во всех трёх нулевые
счётчики missing/late/deadline/overflow/expired TX/CRC и ASIO time errors.
Длительная квалификация 64×64 этой проверкой не заявляется.
Меню каналов сохраняет маски `81` в 8-канальном режиме и
`8000000000000001` в 64-канальном, без изменения физических номеров.
Тест настоящего Shell icon прошёл подключение, отключение, переподключение,
восстановление после TaskbarCreated, открытие настроек и выход из открытой панели.

### CPU, установка и образ

Точная нагрузка службы Pi по `/proc/TID/schedstat` за 30 секунд активного
потока; проценты одного CPU, подтверждены cgroup cpu.stat:

| Ядро | CPU AoIP |
|---|---:|
| CPU0 / RX | 2,20% |
| CPU1 / TX + control/reporter | 7,69% |
| CPU2 | 0,00% |
| CPU3 | 0,00% |

После перезагрузки в ожидании клиента: CPU0/CPU2/CPU3 = 0,00%,
CPU1 = 0,0013% одного CPU за 30 секунд; аудио RX/TX спят.
Windows GetThreadTimes за 180 секунд: audio 5,84%, RX 3,97%, TX 4,40%
одного логического CPU на поток. Это CPU службы/потоков, а не общая
нагрузка системы. Короткопериодный RT нельзя оценивать только по jiffies
`/proc/stat`: они заметно занижали нагрузку в этой конфигурации.

Нативные CTest 4/4, Windows CTest 4/4 прошли. Runtime и SDK DEB 2.2.0-1
установлены на Pi; независимая программа через `find_package(Pi5AoIP 2.2)`
собралась и распознала Pi5/PREEMPT_RT. После перезагрузки службы AoIP,
LAN tuning и governor active/enabled; RX CPU0/FIFO70, TX CPU1/FIFO70,
control/reporter CPU1/SCHED_OTHER. CPU2/CPU3 не используются потоками AoIP.
Wi-Fi, Bluetooth, USB, Ethernet, GPIO доступны, `throttled=0x0`.

Новый 4-ГиБ образ обновлён на ПК из ранее сохранённого через Ethernet образа;
в него включены нативно проверенные DEB 2.2. FAT boot сохранился побайтно,
ext4 и содержимое проверены. Новый образ на отдельный носитель не записывался
и отдельно не загружался. Аналоговый ADC/DAC/I2S backend пока отсутствует:
все аудиотесты относятся к цифровому синтетическому транспорту.
